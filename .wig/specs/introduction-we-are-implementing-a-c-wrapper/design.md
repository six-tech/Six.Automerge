# Design: 100% Automerge API Coverage + Rich Text Support

## Architecture Overview

All new APIs follow the existing 3-layer pattern:

```
Automerge 0.7.3 Rust crate (AutoCommit, ReadDoc, Transactable, SyncDoc)
        │
        ▼
┌──────────────────────────────────────────────────────────┐
│  Rust FFI  (libs/Six.Automerge.FFI/native/src/)           │
│  doc.rs  — NEW: ~35 additional methods on AutomergeDoc    │
│  sync.rs — NEW: 2 additional methods                      │
│  types.rs — NEW: ~8 new FFI types                         │
├──────────────────────────────────────────────────────────┤
│  Generated P/Invoke  (generated/Interop.g.cs)             │
│  Auto-generated by Interoptopus after Rust changes        │
├──────────────────────────────────────────────────────────┤
│  C# High-Level  (libs/Six.Automerge/src/)                 │
│  AutomergeDocument — NEW: ~40 additional methods          │
│  + New types: ExpandMode, AutomergeSpan, AutomergeCursor  │
└──────────────────────────────────────────────────────────┘
```

## New FFI Types (types.rs)

### AutomergeExpandMark — Mark expansion behavior

```rust
#[ffi_type]
#[repr(C)]
pub enum AutomergeExpandMark {
    Before = 0,
    After = 1,
    Both = 2,
    None = 3,
}
```

Maps to Automerge's `ExpandMark` enum. Used in `mark()` and `unmark()`.

### AutomergeSpanKind — Discriminant for span union

```rust
#[ffi_type]
#[repr(C)]
pub enum AutomergeSpanKind {
    Text = 0,
    Block = 1,
}
```

### AutomergeSpan — Flat discriminated union for spans

```rust
#[ffi_type]
pub struct AutomergeSpan {
    pub kind: AutomergeSpanKind,
    // Text variant fields (valid when kind == Text):
    pub text: ffi::String,
    pub marks: ffi::Vec<AutomergeMarkData>,
    // Block variant fields (valid when kind == Block):
    pub block_obj_id: AutomergeObjId,
    pub block_type: ffi::String,
    pub block_parents: ffi::Vec<ffi::String>,
    pub block_attrs_json: ffi::String, // JSON string for arbitrary block attributes
}
```

**Design decision**: Block attributes use JSON string because block markers can have arbitrary key-value properties. The `block_type` and `block_parents` are extracted as first-class fields since they're always present in the rich text schema. Other attributes go into `block_attrs_json`.

**Zero-copy rationale**: Text content and mark data use flat FFI structs. Only block attributes (rarely accessed, arbitrarily nested) use JSON.

### AutomergeValue — Unified scalar + object value

```rust
#[ffi_type]
pub struct AutomergeValue {
    pub is_object: bool,
    // Valid when !is_object:
    pub scalar: AutomergeScalarValue,
    // Valid when is_object:
    pub obj_id: AutomergeObjId,
    pub obj_type: AutomergeObjectType,
}
```

Used for `get_all()`, `values()`, and range query results.

### AutomergeConflictValue — Value with originator info for get_all

Reuses `AutomergeValue` since `get_all` returns `Vec<(Value, ExId)>`:

```rust
#[ffi_type]
pub struct AutomergeConflictValue {
    pub value: AutomergeValue,
    pub op_id: ffi::String,  // ExId as string for conflict identification
}
```

### AutomergeCursor — Opaque cursor handle

```rust
#[ffi_type]
pub struct AutomergeCursor {
    pub bytes: ByteArray,
}
```

Cursors are opaque byte arrays that can be persisted and restored.

### AutomergePathElement — Object graph path segment

```rust
#[ffi_type]
pub struct AutomergePathElement {
    pub obj_id: AutomergeObjId,
    pub prop_type: u8,       // 0 = map key, 1 = list index
    pub key: ffi::String,    // Map key (valid when prop_type == 0)
    pub index: u64,          // List index (valid when prop_type == 1)
}
```

### AutomergeSaveOptions — Configurable save

```rust
#[ffi_type]
pub struct AutomergeSaveOptions {
    pub deflate: bool,   // Enable DEFLATE compression (default: true)
}
```

## FileSystem Storage Adapter Review

The existing `FileSystemStorageAdapter` is a faithful C# port of the TypeScript `NodeFSStorageAdapter`. Key areas to verify:

1. **Sharding logic**: `GetFilePath()` matches TS (`firstKey[0:2] / firstKey[2:] / ...remainingKeys`)
2. **Cache invalidation**: TS uses simple dict cache; C# uses `MemoryCache` with sliding expiration (acceptable enhancement)
3. **RemoveRange vs rimraf**: TS uses `rimraf`; C# uses `Directory.Delete(recursive: true)` (functionally equivalent)
4. **LoadRange deduplication**: TS deduplicates cache + disk keys; C# deduplicates via dictionary in `LoadRange` (matches)
5. **Thread safety**: C# adds `SemaphoreSlim` (not in TS — acceptable for .NET environment)
6. **GetChunkInfo override**: C# adds efficient file-metadata-only query (not in TS — beneficial addition)

**Expected outcome**: Approve with no changes needed, or minor adjustments if review finds discrepancies.

```rust

    // May need: InvalidCursor, InvalidSpan if those error paths arise
```

## Build Pipeline

No changes to the build pipeline. The existing flow is:

1. `scripts/build-ray-automerge-ffi.cs` detects Rust source changes (checksum-based)
2. `cargo build --release` compiles Rust crate with new functions
3. Interoptopus codegen (`codegen/`) regenerates `Interop.g.cs`
4. `dotnet build` compiles C# with new P/Invoke bindings

Sprint 1 verifies this pipeline works before any new code is added.
