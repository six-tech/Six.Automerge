## Sprint 1: Core Build Scripts & Rust Configuration

Create the foundation scripts and Rust toolchain configuration, modeled on the WebView project pattern.

- [ ] Create `scripts/build-native.cs` — incremental Rust compilation script. Port the approach from `d:\Work\projects\RayX\RayX.Avalonia.Controls.WebView\scripts\build-native.cs` but adapted for `six_automerge` crate. Support `--target-os`, `--target-arch`, `--run-codegen`, `--force`, `--verbose` flags. Auto-detect host platform when no flags given. Output artifacts to `artefacts-rust/{os}-{arch}/libsix_automerge-{os}-{arch}.{ext}`. Include checksum-based incremental caching with `build-info-ffi.json`. Apply release optimizations (LTO, single codegen unit, symbol stripping, opt-level 3, panic=abort). Handle the codegen step (Interoptopus `cargo run` on codegen crate) when `--run-codegen` is passed. Map target os+arch to Rust target triples: `windows-x64` -> `x86_64-pc-windows-msvc`, `windows-arm64` -> `aarch64-pc-windows-msvc`, `linux-x64` -> `x86_64-unknown-linux-gnu`, `linux-arm64` -> `aarch64-unknown-linux-gnu`, `macos-x64` -> `x86_64-apple-darwin`, `macos-arm64` -> `aarch64-apple-darwin`. - [ ] Create `scripts/copy-native-libs.cs` — native lib deployment script. Port from `d:\Work\projects\RayX\RayX.Avalonia.Controls.WebView\scripts\copy-native-libs.cs`. Accept `--target-os`, `--target-arch`, `--output-dir`, `--artefacts-dir` flags. Copy from `artefacts-rust/{os}-{arch}/` to output directory, stripping platform suffix from filename (`libsix_automerge-windows-x64.dll` -> `libsix_automerge.dll`). Also copy to `runtimes/{rid}/native/` subdirectory. Platform-to-RID mapping: `windows-x64` -> `win-x64`, `windows-arm64` -> `win-arm64`, `linux-x64` -> `linux-x64`, `linux-arm64` -> `linux-arm64`, `macos-x64` -> `osx-x64`, `macos-arm64` -> `osx-arm64`. Auto-detect current platform when no flags provided.
- [ ] Create `libs/Six.Automerge.FFI/native/rust-toolchain.toml` with `channel = "stable"` and all 6 target triples. Create `libs/Six.Automerge.FFI/native/.cargo/config.toml` with linker config for cross-compilation targets (at minimum: `[target.aarch64-unknown-linux-gnu] linker = "aarch64-linux-gnu-gcc"`).
- [ ] Set up `artefacts-rust/` directory at repo root. Create `artefacts-rust/.gitignore` that ignores all files except itself (`*` then `!.gitignore`). Update root `.gitignore` to ensure `artefacts-rust/` subdirectories with artifacts are ignored (add `artefacts-rust/*/` pattern if not already covered).

## Sprint 3: Publish Script & Pack Updates

Create the release orchestrator script, update pack.cs, and add new menu entries to runner.cs.

- [ ] Create `scripts/publish.cs` — full release orchestrator. Use `CliWrap` and `Spectre.Console` (same as existing scripts). CLI args: `--version <semver>` (required), `--feed <pack-only|local|dev|staging|prod>` (default: pack-only), `--skip-tests`, `--skip-native-build`, `--create-release`, `--dry-run`. Pipeline: (1) optionally run `build-native.cs` for current platform, (2) `dotnet build --configuration Release -p:SkipRustBuild=true`, (3) optionally run tests via `dotnet tests-run.cs`, (4) `dotnet pack --configuration Release -o packages/ -p:SkipRustBuild=true -p:Version={version}`, (5) `git tag v{version}`, (6) if `--create-release`: `gh release create v{version} --title "v{version}" --generate-notes` then attach all files from `artefacts-rust/*` as release assets via `gh release upload`, (7) if feed != pack-only: push `.nupkg` files from `packages/` to target feed using `dotnet nuget push`, (8) cleanup `packages/` directory. Environment variables for NuGet feeds follow existing convention from `pack.cs`. Use `gh` CLI for GitHub release (available in CI and installable locally). Show clear Spectre.Console status output at each step. `--dry-run` prints what would happen without executing.
- [ ] Update `scripts/pack.cs` if needed — ensure it works with the new artifact structure. The main change: pack.cs currently builds each project individually. It should pass `-p:SkipRustBuild=true` during build/pack since the Rust artifacts are expected to already be in `artefacts-rust/`. Also add a `--pack-only` mode that skips publishing entirely (only builds and creates `.nupkg` files). Verify `dotnet scripts/pack.cs -- --local` works end-to-end with the new pipeline.
- [ ] Update `scripts/runner.cs` interactive menu: add entries for `build-native.cs` ("Build native Rust library") and `publish.cs` ("Publish release"). Keep existing entries. Maintain alphabetical or logical ordering.
- [ ] Test the pack workflow locally: run `dotnet scripts/pack.cs -- --local` and verify `.nupkg` files are created with native libs in `runtimes/{rid}/native/` paths. Inspect the package contents to confirm the RID structure. If only the current platform's artifact exists, verify the package contains only that platform's native lib (expected behavior for local dev).

## Sprint 4: GitHub Actions Workflow

Create the comprehensive CI/CD workflow and delete the legacy workflow.

- [ ] Delete `.github/workflows/pr-test.yml`.
- [ ] Create `.github/workflows/build-test-publish.yml` with `workflow_dispatch` trigger. Inputs: `version` (string, required), `feed` (choice: pack-only/local/dev/staging/prod, default: pack-only), `create_release` (boolean, default: true). Set `DOTNET_VERSION: 10.0.100-preview.6` as env var. Permissions: `contents: write` (for creating releases/tags), `packages: read`.
- [ ] Add `build-native` job with matrix strategy for 6 platform targets. Matrix: `[{target_os: windows, target_arch: x64, runner: windows-latest}, {target_os: windows, target_arch: arm64, runner: windows-latest}, {target_os: linux, target_arch: x64, runner: ubuntu-latest}, {target_os: linux, target_arch: arm64, runner: ubuntu-latest}, {target_os: macos, target_arch: x64, runner: macos-13}, {target_os: macos, target_arch: arm64, runner: macos-14}]`. Steps: checkout, setup .NET SDK, setup Rust toolchain (use `dtolnay/rust-toolchain@stable`), install cross-compilation tools (linux-arm64: `sudo apt-get install gcc-aarch64-linux-gnu`), run `dotnet scripts/build-native.cs -- --target-os ${{ matrix.target_os }} --target-arch ${{ matrix.target_arch }} --force --verbose`, upload `artefacts-rust/${{ matrix.target_os }}-${{ matrix.target_arch }}/` as artifact named `native-${{ matrix.target_os }}-${{ matrix.target_arch }}`.
- [ ] Add `verify-codegen` job (runs in parallel with `build-native`, on `ubuntu-latest`). Steps: checkout, setup .NET + Rust, run `dotnet scripts/build-native.cs -- --run-codegen --force --verbose`, verify no diff: `git diff --exit-code libs/Six.Automerge.FFI/generated/Interop.g.cs`. If diff exists, fail with message telling developer to run codegen locally and commit the result.
- [ ] Add `test` job (needs: `build-native`). Runs on `ubuntu-latest`. Steps: checkout, setup .NET, verify Docker, restore dependencies, download `native-linux-x64` artifact into `artefacts-rust/linux-x64/`, build with `dotnet build --configuration Release -p:SkipRustBuild=true`, run tests with `dotnet tests-run.cs` (from `scripts/` working directory).
- [ ] Add `release` job (needs: `[build-native, verify-codegen, test]`). Runs on `ubuntu-latest`. Steps: checkout, setup .NET, download all 6 `native-*` artifacts — use `actions/download-artifact@v4` with pattern `native-*` and merge-multiple, then restructure downloaded directories so each platform's files are under `artefacts-rust/{os}-{arch}/`. Run `dotnet scripts/publish.cs -- --version ${{ inputs.version }} --feed ${{ inputs.feed }} --skip-native-build --skip-tests ${{ inputs.create_release && '--create-release' || '' }}`. Set env vars: `GH_TOKEN: ${{ secrets.GITHUB_TOKEN }}` plus NuGet feed secrets (`NUGET_FEED_*` vars from repository secrets, conditionally used based on feed input).
