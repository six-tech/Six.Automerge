# Implementation Plan: DemoApp.CollaborativeEditor Issues 3

## Sprint 1: Replace RichTextEditor with Plain TextBox + Storage Isolation

This sprint fixes the two simpler issues: broken selection rendering and storage file contention between replicas.

- [ ] Replace `RichTextEditor` with a plain `TextBox` in `EditorWindow.axaml`. Remove the `xmlns:controls` namespace import. Set `Name="LocalEditor"`, `AcceptsReturn="True"`, `AcceptsTab="True"`, `TextWrapping="Wrap"`, bind `Text="{Binding DocumentText, Mode=TwoWay}"`, add `Watermark="Start typing here..."`. Keep the same `Margin="8"` and `DockPanel` positioning.
- [ ] Hide the formatting toolbar buttons in `EditorWindow.axaml`: wrap Bold, Italic, Underline ToggleButtons and their adjacent Separator in a `StackPanel` with `IsVisible="False"`. Remove the `Window.KeyBindings` section (Ctrl+B/I/U). Keep the Save and Export JSON buttons visible.
- [ ] Update `EditorWindow.axaml.cs` to work with plain TextBox: change `LocalEditor.PropertyChanged` handler to use `TextBox.CaretIndexProperty`, `TextBox.SelectionStartProperty`, `TextBox.SelectionEndProperty` (these are the same Avalonia properties — just remove the `RichTextEditor.` prefix and `IsEditorFocused` check). Remove `BoldButton.Click`, `ItalicButton.Click`, `UnderlineButton.Click` handlers. Remove `LocalEditor.AddHandler(KeyDownEvent, OnEditorKeyDown, ...)`. Remove `OnEditorKeyDown` and `ExecuteFormatCommand` methods.
- [ ] Modify `RepoService.StorageDirectory` property to read `REPLICA_INDEX` env var. When set, append `/replica-{index}` to the base storage path. When not set, use the default path (unchanged behavior for standalone runs).
- [ ] Update `infra/Infra.AppHost/AppHost.cs`: replace the CollaborativeEditor `.WithReplicas(4)` line with an explicit loop creating 3 individual project resources (`collaborative-editor-0`, `collaborative-editor-1`, `collaborative-editor-2`), each with `.WithEnvironment("REPLICA_INDEX", i.ToString())`. Apply the same pattern to CollaborativeDrawing and CollaborativeTaskBoard entries.
- [ ] Update existing unit tests in `tests/DemoApp.Shared.Tests/` for `RepoService.StorageDirectory` to cover the `REPLICA_INDEX` env var scenarios (with and without the env var set). Run `dotnet test` on affected test projects to verify all tests pass.
- [ ] Build and run the application via Aspire AppHost (`dotnet run --project infra/Infra.AppHost`). Use `six-avalonia-mcp` to verify: (a) plain TextBox renders and accepts input, (b) formatting buttons are hidden, (c) status bar still works, (d) each replica has its own storage directory.

## Sprint 2: Server-Side Document Peer Tracking

This sprint adds the server infrastructure for tracking which clients are editing which documents, and exposes this data via SignalR hub methods and callbacks.

- [ ] Create `PeerInfoDto` in `libs/Six.Automerge.Repo.Network.SignalR.Abstractions/src/Models/PeerInfoDto.cs` as a MessagePack-serializable DTO with `PeerId` (string, Key 0) and `Metadata` (PeerMetadataDto?, Key 1). Follow the same MessagePack patterns as existing DTOs (MessageDto, PeerHandshakeDto).
- [ ] Add `OnDocumentPeersChanged(string documentId, List<PeerInfoDto> peers)` method to `IDocumentsHubClient` interface. This is the server-to-client callback for real-time peer list updates.
- [ ] Add `GetDocumentPeers(string documentId)` returning `Task<List<PeerInfoDto>>` and `GetDocumentPeerCount(string documentId)` returning `Task<int>` to the `IDocumentsHub` interface. These are client-to-server RPC methods.
- [ ] Create `DocumentPeerTracker` service in `apps/Server.Api/src/Services/DocumentPeerTracker.cs`. Use `ConcurrentDictionary<string, ConcurrentDictionary<string, PeerInfoDto>>` for document→peers and `ConcurrentDictionary<string, HashSet<string>>` for peer→documents (reverse index for disconnect cleanup). Implement: `AddPeerToDocument`, `RemovePeerFromDocument`, `RemovePeerFromAllDocuments`, `GetDocumentPeers(docId, excludePeerId)`, `GetDocumentPeerCount(docId, excludePeerId)`. Register as singleton in `ServiceCollectionExtensions.AddSyncServer()`.
- [ ] Update `DocumentsHub` in `apps/Server.Api/src/Hubs/DocumentsHub.cs`: (a) Inject `DocumentPeerTracker`. (b) In `SendMessage`, after auto-subscribing, call `tracker.AddPeerToDocument(documentId, peerInfo)` and broadcast `OnDocumentPeersChanged` to the group via `Clients.Group(documentId).OnDocumentPeersChanged(documentId, tracker.GetDocumentPeers(documentId, callerPeerId))`. Use `Clients.Client(connectionId)` for per-client peer lists that exclude that client's own entry. (c) In `SubscribeToDocument`, do the same tracking. (d) In `OnDisconnectedAsync`, call `tracker.RemovePeerFromAllDocuments(peerId)` and broadcast updated peer lists to each affected document group. (e) Implement `GetDocumentPeers` and `GetDocumentPeerCount` hub methods using the tracker (exclude calling peer).
- [ ] Write unit tests for `DocumentPeerTracker`: add/remove peers, concurrent operations, disconnect cleanup, peer exclusion. Add to `tests/Server.Api.Tests.Unit/`.
- [ ] Build Server.Api and run `dotnet test tests/Server.Api.Tests.Unit` to verify all tests pass (existing + new).

## Sprint 3: Client-Side Peer Count Integration + End-to-End Testing

This sprint wires up the client to receive and display real document peer counts from the server.

- [ ] Update `SignalRNetworkAdapter` in `libs/Six.Automerge.Repo.Network.SignalR.Client/src/SignalRNetworkAdapter.cs`: (a) Add `DocumentPeersChanged` event of type `EventHandler<DocumentPeersChangedEventArgs>`. (b) In `ConnectAsyncInternal`, register handler for `OnDocumentPeersChanged` callback — deserialize and raise the event. (c) Add `GetDocumentPeersAsync(string documentId)` method that invokes the `GetDocumentPeers` hub method via the connection.
- [ ] Create `DocumentPeersChangedEventArgs` in `libs/Six.Automerge.Repo.Network.SignalR.Client/src/` (or in Abstractions if shared) with `DocumentId` (string) and `Peers` (List<PeerInfoDto>) properties.
- [ ] Update `RepoService` in `apps/DemoApp.Shared/src/RepoService.cs`: (a) Add `DocumentPeerCount` property (int, with change notification via `DocumentPeerCountChanged` event). (b) Subscribe to `_networkAdapter.DocumentPeersChanged` in `InitializeAsync` and update `DocumentPeerCount` from the event. (c) Add `GetDocumentPeersAsync(string documentId)` method that delegates to the network adapter. (d) Change `PeerCountChanged` event dispatch to use `DocumentPeerCount` for the count rather than the Repo-level `_peerCount` (or add a separate event — keep `_peerCount` for Repo-level tracking if useful for diagnostics).
- [ ] Update `EditorWindow.axaml.cs`: After `SetTextDocument` + `ShowEditorAsync`, call `repoService.GetDocumentPeersAsync(documentId)` to get the initial peer count and update both `_statusBarVm.PeerCount` and `vm.UpdateConnectionStatus(...)`. Wire `repoService.DocumentPeerCountChanged` to update the status bar and sync status when peers change.
- [ ] Update existing tests to account for the new peer count flow. Ensure `EditorViewModelTests` for `UpdateConnectionStatus` still pass. Add tests for `RepoService.DocumentPeerCount` and the new event. Run `dotnet test` on all affected test projects.
- [ ] Build and run the full stack via Aspire AppHost. Use `six-avalonia-mcp` to verify end-to-end: start 3 replicas, create a document on replica-0, join from replica-1 and replica-2. Verify that all clients show correct peer counts (replica-0 shows "Syncing (2 peers)", etc.). Verify typing syncs correctly across all replicas. Verify that when a replica is closed, other replicas' peer counts decrease.
